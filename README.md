# 독후감·문학 공모전 모아보기

초·중·고 학생과 학부모가 **지금 접수할 수 있는 독후감·문학작품(시·수필·소설 등) 공모전**을 한눈에 찾는 정적 웹사이트입니다.
빌드 도구 없이 HTML·CSS·JavaScript만으로 만들었고, GitHub Pages에 무료로 올릴 수 있습니다.

## 폴더 구조

```
index.html          페이지 뼈대
css/style.css       디자인 (모바일 우선 반응형)
js/app.js           데이터 읽기·필터·정렬·화면 그리기
data/contests.json  ★ 공모전 데이터 — 사이트에 보이는 내용은 모두 여기서 나옵니다
crawler/crawl.py    공모전 사이트에서 독후감·문학작품 공모전을 모아 contests.json에 넣는 크롤러
.github/workflows/  GitHub에서 매일 크롤러를 자동 실행하는 설정
.nojekyll           GitHub Pages 설정용 빈 파일 (지우지 마세요)
```

## 정보 출처 목록

### 크롤러가 자동으로 모으는 곳
| 사이트 | 읽는 페이지 | 비고 |
|---|---|---|
| [공모전코리아](https://www.contestkorea.com) | "독후감" 검색 결과, `문학•문예` 분류 목록 → 각 공모전 상세 | 접수기간·대상·시상·주최사 공고 링크가 정리돼 있어 정확도가 가장 높음 |
| [위비티](https://www.wevity.com) | 공모전명 "독후감" 검색 결과, `문학/글/시나리오` 분류 목록 → 각 공모전 상세 | 공모전코리아에 없는 공모전을 보충 |

두 사이트 모두 robots.txt에서 수집을 허용합니다. 크롤러는 요청 사이에 1.5초씩 쉬고, 사이트마다 독후감 검색은 3페이지, 문학 분류 목록은 15페이지까지만 읽습니다.

### 사람이 직접 확인해서 넣을 곳 (크롤링하지 않음)
| 출처 | 이유 |
|---|---|
| 시·도 교육청 홈페이지 공지 | 학생 대상 교육감상 대회가 많지만 사이트마다 구조가 달라 자동 수집이 어려움 |
| 지역 공공도서관 공지 ("○○시 올해의 책 독후감") | 위 공모전 사이트에 올라오지 않는 소규모 대회가 있음 |
| [아이러브콘테스트](https://ilovecontest.com) | robots.txt에서 수집 봇을 막고 있어 자동 수집하지 않음. 눈으로 보고 참고만 함 |

현재 독후감 공모전을 한데 모아 주는 공개 API는 없습니다. 쓸 만한 API가 생기면 크롤러에 출처로 추가하면 됩니다.

## 자동 수집 (크롤러)

### 처음 한 번 준비
1. [python.org](https://www.python.org/downloads/)에서 Python을 설치합니다. 설치 첫 화면에서 **"Add python.exe to PATH"를 꼭 체크**하세요.
2. 이 폴더에서 터미널을 열고 다음을 실행합니다.
   ```
   pip install -r crawler/requirements.txt
   ```

### 실행
```
python crawler/crawl.py --dry-run   # 파일은 그대로 두고 무엇을 찾았는지만 보기
python crawler/crawl.py             # data/contests.json에 반영
```

### 크롤러가 지키는 규칙
- 크롤러가 넣은 항목은 id가 `ck-`(공모전코리아) 또는 `wv-`(위비티)로 시작합니다.
- **직접 넣은 항목(다른 id)은 절대 고치거나 지우지 않습니다.** 같은 공모전이 크롤링되면 직접 넣은 쪽을 남깁니다.
- 실제 공모전을 하나라도 찾으면 `[예시]` 데이터는 지웁니다.
- 마감 후 30일이 지난 크롤링 항목은 지웁니다.
- 문학 분류 목록에는 우수사례·수기·입주작가 모집·강좌 광고 같은 글도 섞여 있어, 제목으로 걸러 문학작품 공모만 넣습니다. 거르는 단어는 `crawl.py`의 `LITERATURE_INCLUDE`, `LITERATURE_EXCLUDE`에 있습니다.
- 문학작품 공모전의 대상은 사이트의 대상 칸과 본문의 "응모 자격"을 보고 정하며, 둘 다 알 수 없으면 `일반`으로 둡니다. 장르는 제목·본문의 단어로 추정하고, 찾지 못하면 `원문 참고`로 표시합니다.
- 지역과 지정도서 여부는 제목·본문을 보고 **추정**합니다. 제목에 "신춘"이 있으면 신문사 신춘문예로 보고 전국, 제목이나 본문에 "전국"이 있으면 전국, 아니면 주최 기관 이름의 시·군으로 시·도를 정합니다. "올해의 책", "대상 도서" 같은 말이 있으면 지정도서로 봅니다. 틀린 항목을 발견하면 그 항목을 복사해 id를 바꿔(예: `ck-` 빼기) 직접 입력으로 넣으세요. 그러면 크롤러가 더 이상 덮어쓰지 않습니다.

### GitHub에서 매일 자동 실행
GitHub에 올리면 `.github/workflows/crawl.yml`이 매일 오전 6시(한국 시간)에 크롤러를 돌리고, 바뀐 내용이 있으면 자동으로 커밋합니다. 그러면 사이트도 함께 갱신됩니다. 저장소의 **Actions** 탭 → "공모전 자동 수집" → **Run workflow**로 바로 실행할 수도 있습니다.

## 공모전 추가하기

1. `data/contests.json`을 엽니다.
2. `"contests": [ ... ]` 안의 마지막 항목 `}` 뒤에 **쉼표(,)** 를 하나 찍고, 아래 템플릿을 붙여 넣은 뒤 값을 바꿉니다.

```json
    {
      "id": "기관약칭-2027-001",
      "title": "공모전 이름",
      "organizer": "주최 기관",
      "target": ["초등", "중등"],
      "region": "서울",
      "startDate": "2027-03-01",
      "endDate": "2027-04-30",
      "bookRequirement": "자유",
      "prize": "대상 1명 상장 및 상금 30만 원",
      "url": "https://공고-원문-주소",
      "source": "기관 홈페이지",
      "updatedAt": "2027-02-20"
    }
```

문학작품 공모전은 `"bookRequirement"` 줄 대신 아래 두 줄을 넣습니다.

```json
      "category": "문학작품",
      "genres": ["시", "수필"],
```

3. 저장하고 GitHub에 커밋하면 1~2분 뒤 사이트에 반영됩니다.

### 항목 설명

| 항목 | 쓰는 법 |
|---|---|
| `id` | 다른 항목과 겹치지 않는 이름. 예: `seoul-lib-2027-001` |
| `category` | `"독후감"` 또는 `"문학작품"`. 적지 않으면 독후감으로 봅니다. |
| `title` | 공모전 이름 |
| `organizer` | 주최 기관 |
| `target` | 대괄호 안에 `"초등"`, `"중등"`, `"고등"`, `"일반"` 중 해당하는 것을 모두 씁니다. 예: `["초등", "중등"]` |
| `region` | `"전국"` 또는 `서울`, `부산`, `대구`, `인천`, `광주`, `대전`, `울산`, `세종`, `경기`, `강원`, `충북`, `충남`, `전북`, `전남`, `경북`, `경남`, `제주` 중 하나 |
| `startDate`, `endDate` | 접수 시작일·마감일. 반드시 `"2027-03-01"`처럼 `연-월-일` 형식으로 씁니다. 마감일 당일까지 접수중으로 표시됩니다. |
| `bookRequirement` | (독후감) `"지정도서"` 또는 `"자유"` |
| `genres` | (문학작품) 대괄호 안에 장르를 씁니다. 예: `["시", "수필", "소설"]` |
| `prize` | 시상 내용 (자유롭게) |
| `url` | 원문 공고 주소. `https://`로 시작해야 합니다. |
| `source` | 정보를 어디서 봤는지 |
| `updatedAt` | 이 정보를 마지막으로 확인한 날짜 |

**접수중·예정·마감 상태는 따로 적지 않습니다.** 사이트가 오늘 날짜(한국 시간)와 시작일·마감일을 비교해서 자동으로 계산합니다.

### 자주 하는 실수

- 마지막 항목 뒤에 쉼표를 남김 → `}` 다음 `]` 앞에는 쉼표가 없어야 합니다.
- 항목 사이에 쉼표를 빠뜨림
- 따옴표를 빠뜨리거나 한글 따옴표(“ ”)를 씀 → 항상 영문 큰따옴표 `"`를 씁니다.
- 날짜를 `2027.3.1`처럼 씀 → `2027-03-01`

저장하기 전에 [JSONLint](https://jsonlint.com) 같은 검사기에 붙여 넣어 보면 문법 오류를 쉽게 찾을 수 있습니다.
값이 잘못된 항목은 화면에 표시되지 않고, 페이지 아래쪽에 어떤 항목이 왜 빠졌는지 안내가 나옵니다.

## 내 컴퓨터에서 미리 보기

`index.html`을 더블클릭해서 열면 브라우저 보안 정책 때문에 데이터를 읽지 못합니다. 간단한 로컬 서버를 띄워야 합니다.

- **Python이 있으면:** 이 폴더에서 `python -m http.server 8000`을 실행하고 브라우저에서 http://localhost:8000 을 엽니다.
- **VS Code를 쓰면:** Live Server 확장을 설치한 뒤 `index.html`에서 오른쪽 클릭 → "Open with Live Server"를 선택합니다.

## GitHub Pages로 배포하기

1. GitHub에 새 저장소를 만들고 이 폴더의 파일을 모두 올립니다.
2. 저장소 **Settings → Pages**로 갑니다.
3. **Source**를 "Deploy from a branch"로 두고, Branch를 `main`, 폴더를 `/ (root)`로 고른 뒤 Save를 누릅니다.
4. 잠시 뒤 `https://<사용자이름>.github.io/<저장소이름>/` 주소로 사이트가 열립니다.

## 기능

- 전체·독후감·문학작품 탭으로 나눠 보기 (탭마다 건수 표시)
- 문학작품 공모전은 카드에 장르(시·수필·소설 등) 표시
- 마감 임박 순 정렬 (접수중 → 예정 → 마감)
- 필터: 대상(여러 개 선택), 지역(시·도를 고르면 전국 공모전도 함께 표시), 상태
- 마감된 공모전은 기본으로 숨기고, 토글을 켜면 표시
- D-day 표시 (마감 7일 이내는 주황색으로 강조)
- 필터 상태가 주소창에 반영돼서 링크를 공유하면 같은 결과가 보입니다
